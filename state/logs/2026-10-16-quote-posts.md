# 2026-10-16 — Quote posts + FEP-044f (docs/quote-posts.md implementation)

## What changed

Implemented `docs/quote-posts.md` (canonical FEP-044f outbound, legacy inbound compat, Misskey API projection, authorization workflow) with review-driven fixes on top of the prior session's scaffold:

- **Domain** (`src/domain/quote.rs`, new): `QuoteReference` + 7-state `QuoteAuthorizationState` (`api_status`, `allows_transition`). `Revoked→Approved/ApprovedByException/Pending` allowed (revocation is not terminal — fresh stamp can re-approve); `request_activity_uri` validated as `http(s)` when present.
- **Wire boundary** (`src/activitypub/quotes.rs`, new): 5-carrier inbound normalization (canonical `quote` + expanded IRI, `_misskey_quote` both slash variants, `quoteUrl`, `quoteUri`/`quoteURL`, e232 `Link` with Misskey `rel`), alias collapsing, canonical-wins with deduped conflict list, stamp verify (5 doc checks + stamp-host == author-host), exceptions by structured identity, `RE:`/`QT:` (case-insensitive) terminal-fallback dedup, correct e232 `mediaType` (`application/ld+json; profile=…`), context entries for `_misskey_quote`/`quoteUrl`.
- **Outbound**: `render_note_object` emits canonical + all three legacy aliases + advisory `interactionPolicy.canQuote` (never `manualApproval`) + single e232 Link + single `RE:` fallback on serialized content only (stored body untouched; no fallback for restricted or unresolved-visibility targets). `QuoteRequest` inlines the quote Note **with** `@context`. Stamp endpoint `GET /users/{id}/stamps/{stamp}` (404 for unknown/revoked/protected targets; never embeds the quote Note).
- **Workflow** (`src/application/commands/inbound/quotes.rs`, new + `notes.rs` creation): local same-server public/home **non-local-only** quotes → `ApprovedByException`, self/mention → exception, remote → `Pending` + `QuoteRequest` job in the same txn (request URI stored only when a job was actually enqueued); renote of deleted target rejected; inbound `QuoteRequest` auto-approves public/unlisted + exceptions and **Ignores** (no `Reject` oracle) when the requester is not entitled to see a non-public target, `Reject`s only entitled quoters; inbound `Accept` verifies the stamp before the txn (malformed URI → `Ignored`, transient fetch → rate-limited `QuoteStampReverify` job, invalid content → `Ignored` never `Rejected`); `Reject` retains relation + projection; stamp `Delete` → `Revoked` + forward, converging replays to `Duplicate`.
- **Inbox** (`src/federation/inbox.rs`): `QuoteRequest`/`Accept`/`Reject`/stamp-`Delete` arms with signature + actor-authority + `is_recorded` replay gates (including `Delete`); `Accept` routes to the quote path only for known `QuoteRequest` shapes/IDs (never steals `Accept(Follow)` with a `result` field); stamp-`Delete` authority is the stamp author actor (not host-wide); recursion-guarded one-level quote resolution; remote-lookup cache path retains quotes as `Unapproved` and now sets `renote_of` when the target resolves (no fabricated `renoteId` otherwise).
- **Storage** (`src/persistence/redb/mod.rs`): `set_quote_authorization` (+in-txn variant), stamp table, request/stamp lookups, all five `record_quote_*` dedup-atomic methods; `record_quote_stamp_delete` flips the backing stamp row `revoked=true` **in the same txn** (so revoked stamps stop dereferencing) while retaining the URI for replay convergence.
- **API** (`packers.rs`): `quoteAuthorizationStatus` on quotes only; `quoteTargetUri` (unresolved-but-disclosable) / `quoteTargetUnavailable` (protected target, `renote` null, no URI leak); rejected/unapproved quotes still render subject to visibility.
- **Worker** (`src/jobs/worker.rs`): `QuoteStampReverify` with standard backoff/quarantine (transient retries, invalid content completes quietly, decided/gone quotes converge).

## Open questions / known limitations

1. **FoundationDB adapter is a 0-byte stub** (`src/persistence/foundationdb/mod.rs`): the "both adapters green" gate cannot pass until Phase 4 builds it; Group Q cases are written backend-generic so FDB inherits them unchanged.
2. **Stamp authority is host-granular**: `verify_stamp_for_quote` requires stamp-host == quoted-author-host + `attributedTo` match over a signed dereference; a malicious co-host user could mint a stamp with a copied `attributedTo` at their own path. Needs per-actor object authority (or documented trust) in a follow-up.
3. **`StampFetchPending` retry is enqueued non-atomically** (separate `enqueue_jobs` after transport-accept): a crash in the window loses the retry; recovery depends on remote re-delivery. Acceptable for MVP, should move into the dedup txn later.
4. **No negative dedup for invalid stamps**: replays of bogus-`Accept`s re-fetch over the network each time (bounded by timeouts/size/redirects, but unlimited count). Consider `Ignored`-with-dedup/TTL + per-target rate limits.
5. **Quote lookups are full-table scans** (`find_note_by_quote_request/stamp`): fine at interop scale, needs a secondary index before production load (every bare-IRI `Reject`, incl. follow-Rejects, hits the scan).
6. **Sharkey deliberately disables outbound FEP `quote`** (hides Mastodon's fallback link): Sharkey→pinetree quotes arrive legacy-only (`Unapproved`) by design; full request→accept cycle is therefore pinetree↔pinetree only (covered in `tests/federation_interop.rs` quote phase + live pt3/pt4 checks).
