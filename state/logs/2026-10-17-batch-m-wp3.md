## Decisions and DIVERGENCES (recorded; do not "fix" back)

- **Refusal on moderator/admin targets applies to BOTH endpoints** (guide §3.1 blanket rule): suspend carries upstream's verbatim `cannot suspend moderator account` (`suspend-user.ts:46`); unsuspend carries pinetree-constructed `cannot unsuspend moderator account`. DIVERGENCE: upstream `unsuspend-user.ts` has no check (apparent oversight); both upstream refusals throw untyped `Error`s → `500 INTERNAL_ERROR` (`ApiCallService.ts:#onExecError`) while pinetree answers `400 INVALID_PARAM` carrying the message (WP1 precedent).
- **Missing target** → `NO_SUCH_USER` (pinetree UUID `fcd2eef9-…`, one-UUID-per-code; do NOT copy the guide's `1acefcb5-…`). Upstream throws untyped `user not found` → 500. DIVERGENCE.
- **Sign-in ordering**: pinetree checks `is_suspended` AFTER password verification (keeps its existence-hiding sign-in); upstream checks before the password (`SigninApiService.ts:138`, 403 with per-endpoint id `e03a5f46-…` — NOT copied; pinetree's `USER_SUSPENDED` id `a8c724b3-…`). DIVERGENCE.
- **Fan-out shape**: one sweep job per outbound concern (`SuspendBroadcast`, `UnfollowAll`) — not literally one job — each expanding at run time (guide §11 boundedness: `MAX_JOBS_PER_TXN` 500, 64 KiB payload cap, FDB ~5 s/10 MiB). Outgoing-follow rows are deleted at worker time in the sweep batches (each row delete + its job = one transaction), never in the suspend transaction.
- **No-change suspend/unsuspend calls are NOT no-ops** (upstream `suspend()` re-logs and re-runs its post-suspend work unconditionally) — unlike `admin/reject-quotes`.
- **Remote targets take flag + log + follow-request teardown only** (sweeps are local-only). DIVERGENCE: upstream `unFollowAll` runs for remote targets too (deletes their edges to local accounts and delivers `Reject` per edge). Note as a possible later revisit in open questions.
- **Sweep recipient set** = `AccountStore::remote_shared_inboxes` (all known remote `shared_inbox` values; superset of upstream's `followings`-snapshot set — upstream `postSuspend`/`postUnsuspend` "知り得る全SharedInbox"). Accounts without `shared_inbox` are skipped (upstream-exact).
- **Activity shapes**: `Delete(Person)`/`Undo(Delete)` match upstream (`object` = actor URI string, no `to`/`cc`, `published`) PLUS activity ids (`{base}/activities/{id}`, Undo id `{id}/undo` = upstream's `renderUndo` id rule) — upstream renders none; the ids make re-runs re-deliver stable ids for receiver-side dedupe.
- **Stream close is a durable job wired from the command** (house rule: commands never touch sockets; hub.rs doc), not from the store. DIVERGENCE: pinned upstream (Misskey `2026.10.1-alpha.0` AND Sharkey `2025.4.7`) does NOT drop sockets on `userChangeSuspendedState` — it only invalidates caches (`CacheService.ts:145`) and refuses new upgrades (`StreamingApiServerService.ts:80`); pinetree's drop is a deliberate hardening the deliverable required.
- **Suspend semantics** (upstream parity): outgoing follows removed (stay removed), incoming follows kept, follow requests removed in both directions (stay removed). Unsuspend restores sign-in/token/stream/actor-fetch but none of those rows.
