# 2026-10-15 — Checkouts + cargo target moved to ext4

## Why
WSL 9P (`/mnt/c`) round-trips every file access; Node boots/vite and cargo
were the bottleneck. `fedifedifedi/` also turned out to hold a dozen other
projects (mastodon, pixelfed, pleroma, …) — the 5.2G was the whole folder;
only Misskey 1.6G + Sharkey 1.3G moved.

## What changed
- `cp -a` died with its shell midway (1.7G partial); resumed with detached
  `rsync -a` → `/root/fedifedifedi/{misskey,sharkey}` (3.2G), clean log.
  Verified versions (`2026.10.1-alpha.0` / `2025.4.7`) and built entries
  (`backend/built/entry.js`, `backend/built/boot/entry.js`) plus Misskey
  `.config/default.yml`; native modules untouched (same machine/arch).
- `./misskey`, `./sharkey` symlinks repointed to `/root/fedifedifedi/*`.
  Running KEEP-stack processes still use old fds and are unaffected; all new
  launches resolve through the symlinks.
- `.cargo/config.toml` (new, git-ignored via `/.cargo/`): `target-dir =
  "/root/pinetree-target"`.
- Docs: `README.md` prerequisites + `docs/phase-2-interop-howto.md`
  prerequisites carry the ext4 filesystem note.

## Verification (executed)
- Fresh `cargo build --offline` into `/root/pinetree-target`: finished in
  34 s (12 cores), binary 88M.
- `cargo test --offline --lib`: 193/193 green.
- Old trees left in place: `/mnt/c/.../pinetree/target` (14G) and the
  `/mnt/c/.../fedifedifedi` checkouts — delete after a soak period.
