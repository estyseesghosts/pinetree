## Agent protocol (binding, per AGENTS.md)

* `git status --short` before start; respect others' uncommitted work. Parent owns shared files and merges: `docs/*`, `src/application/ports.rs`, `src/persistence/redb/mod.rs` (schema), `src/config.rs`, `src/main.rs`, `src/api/misskey/endpoints/mod.rs` (dispatcher), `tests/conformance.rs`. Subagents propose snippets for shared files, never edit them directly.
* Partition disjoint file sets per work package. Subagents use uniquely-named `tests/gaps_*.rs`, leave changes uncommitted, never `commit/stash/reset/checkout`. Parent stages/commits only its own merged files when told to, early and often (small commits per WP + dated `state/logs/YYYY-MM-DD-gaps-wpN.md`, never rewrite old logs).
* Config rule: every new knob is a JSON `config` serde field (key == field name), optional with sane default, covered in `validate()` + round-trip test in `src/config.rs`. Unknown keys stay hard errors. No env/CLI-only settings; fold `PINETREE_ALLOW_PRIVATE_IPS / DEBUG_FEDERATION / REPLY_REPAIR_LIMIT` into config or document a granted exception.
* Architecture: `domain <- application <- adapters`, one txn commits state + indexes + dedup + bounded jobs; no blobs/unbounded fan-out in txn; FDB 5s/10MB respected by batching (500/batch); public URLs never leak node hostnames; federation input untrusted (size/timeout/redirect/SSRF/signature).

## WP1 — transcode like birchtree (internal ffmpeg, post-commit job)

Copy `birchtree/src/media/transcode.rs` + `processing.rs` semantics, adapted to Misskey `DriveFile` (`url`, `thumbnailUrl`, `properties`): GIF (animated or not) → WebM/VP9 wire `video`; video → WebM/VP9 + Opus (passthrough iff VP9+Opus/no-audio within `max_file_size`: byte-identical if already WebM else `-c copy` into WebM, always serve WebM); stills (JPEG/PNG/BMP/HEIC/HEIF/TIFF/AVIF) → WebP (WebP passthrough, `small` preview also WebP); audio passthrough. Never strip metadata (`-map_metadata 0`, orientation kept as tag, clients apply it). Upload commits metadata (`pending/processing`) + `JobKind::TranscodeMedia` atomically; job runs ffmpeg outside txn to staged tmp, verifies, replaces original blob (no pointer swap), commits `ready` last; crash leaves `pending` (`url` null, never partial) + bounded re-run converges (ffmpeg sniffs content, re-transcode of derived bytes still valid); `ready/failed/missing` no-op; deterministic failures (bad decode, wall/output/RSS breach) commit `failed` → API `422`; storage faults retry then quarantine. Limits: wall 120s, output 64 MiB, RSS 1 GiB; quality WebP q80, VP9 `-crf 30 -b:v 0 -cpu-used 2 -row-mt 1`, Opus 96k source layout. Startup gate: when enabled, `ffmpeg -encoders/-decoders` must show `libvpx-vp9/libopus/libwebp` + `png/mjpeg/gif/bmp/webp/tiff/h264/hevc/mpeg4/vp8/vp9/aac/opus/vorbis/mp3/flac`; missing toolchain = startup error, never silent passthrough; `--no-transcode` (or `transcode.enabled=false`) routes around the module. Files: subagent owns `src/media/transcode.rs` (new, ported), `src/media/processing.rs` (new), `src/jobs/transcode.rs` (new), `tests/gaps_transcode.rs`; proposes `ports.rs` (`TranscodeConfig`, `MediaState`), `redb/mod.rs` (state cols), `config.rs` (knobs), `Dockerfile` (+ffmpeg layer) + `pinetree_container.md` notes.
