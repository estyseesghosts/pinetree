Broad auth audit — no bypass found; findings below
No auth bypass / downgrade / fixation:
- All session-mint paths (do_signin signup.rs:284-299, do_signin_flow signin_flow.rs:252-273, i/2fa/authenticate twofa.rs:351-368) mint fresh generate_random_token() server-side; no attacker-controlled session id → no fixation. - TOTP replay guarded atomically: consume_totp_login (persistence/redb/registry_store.rs:131-219) validates challenge, expiry, and matched_step > last_step in one write txn, then consumes challenge + records step. Cross-challenge same-step reuse rejected; tests tests_auth_totp_p0.rs:291-373 cover challenge replay and cross-challenge replay with recovery.
- 2FA downgrade closed: register refuses when verified (auth_2fa.rs:147); password-less:true refused; legacy true still needs password+TOTP (test cited above).
New / residual issues (all low; none is a bypass):
1. Inconsistent existence/suspension oracle between the two sign-in endpoints — signup.rs:222-258 (do_signin) verifies the password before checking suspended/deleted (existence-hiding, documented signup.rs:248-255), while signin_flow.rs:195-209 returns 404/403/404 before any password check and the username-only step returns 200-captcha for live accounts. So signin-flow lets an unauthenticated caller distinguish unknown/deleted (404) vs suspended (403) vs live (200). Upstream parity per comment, but the two endpoints have opposite disclosure postures. File:line: signin_flow.rs:195-217 vs signup.rs:222-263.
2. Deleted-account second-factor oracle (narrow) — auth_2fa.rs:256-274: deleted accounts are meant to read NO_SUCH_2FA, but storage marks deleted as suspended too, so a pre-deletion challenge presented post-deletion hits USER_SUSPENDED 403 first (test bakes this in, tests_auth_totp_p0.rs:464-478). Distinguishes "had a live challenge then deleted" from "no challenge," within the 5-min TTL only. Low.
3. set_2fa_passwordless(false) without a verified secret is not a no-op success — auth_2fa.rs:206 calls verified_totp, so TOTP-less callers get NO_SUCH_2FA instead of 204. Test at tests_auth_totp_p0.rs:520-527 only covers the already-clear-with-verified case. Minor contract wart.
4. Discarded registry-remove error on expired-challenge prune — auth_2fa.rs:356-359 (let _ = ...registry_remove). Stale expired row lingers; next attempt re-prunes. Fails safe (still returns expired), robustness nit only.
5. register→update-key window locks login — enrol_totp (auth_2fa.rs:108-129) overwrites the verified row with verified:false; until done, verified_totp fails so authenticate_2fa answers NO_SUCH_2FA. Availability nit, no bypass.
6. Log injection: none — log_me_updated_skip fields are server-minted account_id, fixed stage, and error_class() fixed-string taxonomy (observability.rs:170-187); log_event debug-formats values (observability.rs:203-208) so control chars can't forge lines; record_error takes only constant categories. eprintln! signin-history failure (session.rs:213) interpolates only server-side id. Clean.
7. Password hashing/ordering: sound — Argon2 via verify_password_async/hash_password_async off-executor (auth.rs:107-115, session.rs:220-241); rehash failure fails closed (login errors after a correct password — safe, slight availability cost). Timing side-channels negligible under Argon2 + network jitter; throttle-before-lookup in do_signin (signup.rs:210-216) and signin_flow (signin_flow.rs:181-189) with unknown-username failure counting avoids trivial enumeration via throttle.
